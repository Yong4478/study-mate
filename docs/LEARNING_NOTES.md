# 📘 학습 노트 — 과제 목표 6가지를 내 말로 설명하기

과제를 마친 뒤 "스스로 설명할 수 있어야 한다"는 6가지 목표를, 이 프로젝트 코드에 맞춰 정리했습니다.
각 항목의 **한 줄 요약**을 먼저 말하고, 필요하면 **코드 위치**를 보여주며 설명하면 됩니다.

---

## 1. 시계열 데이터 → 요약 정보 → 서비스 활용 흐름

**한 줄 요약**: 날짜별 공부 시간을 모아 통계(합계·평균·최대·최소)와 추세를 계산하고, 그 요약을 화면과 AI 프롬프트 두 곳에서 씁니다.

```
Firestore data 컬렉션 (날짜별 기록 120개)
   → data_service.list_records()      날짜순으로 읽기
   → analysis.build_summary()          기간·개수·통계·추세·월별 합계 계산
   → GET /api/data/summary             화면의 "내 데이터 요약" 카드
   → chat_service.build_system_prompt  AI 시스템 프롬프트에 삽입
```

- **추세 판단**: 최근 7개 기록 평균과 직전 7개 평균을 비교해 +5% 이상이면 상승, −5% 이하면 하락, 그 사이면 유지. 하루하루 값은 들쭉날쭉하니까 7개씩 묶어 평균을 내서 비교합니다.
- **월별 합계**를 넣은 이유: "이번 달 어때?" 같은 질문은 전체 평균만으로는 답할 수 없기 때문입니다.
- 코드: `backend/services/analysis.py` (DB·AI 와 상관없는 순수 함수라 테스트가 쉬움)

## 2. FastAPI 프로젝트를 라우터 / 서비스로 나눈 기준

**한 줄 요약**: 라우터는 "주소와 입출력 형식", 서비스는 "실제 일(DB·분석·AI)"을 맡습니다.

| 계층 | 하는 일 | 예시 |
|---|---|---|
| `routers/` | URL, HTTP 메서드, 요청/응답 스키마, 상태 코드 | `@router.post("/api/data", status_code=201)` |
| `services/` | Firestore 읽기/쓰기, 분석, AI 호출, 대화 저장 | `data_service.create_record()` |
| `core/` | 설정, DB 연결, AI 클라이언트처럼 여러 곳에서 쓰는 기반 | `ai_client.chat_completion()` |
| `schemas.py` | 데이터 모양과 검증 규칙 | `DataCreate`, `ChatRequest` |

- **장점 1 – 재사용**: `/api/chat` 이 요약을 얻을 때 HTTP 로 `/api/data/summary` 를 다시 부르지 않고 같은 서비스 함수 `get_summary()` 를 바로 호출합니다. 도구 호출(`tools.py`)도 같은 서비스 함수를 씁니다.
- **장점 2 – 테스트**: 서비스는 FastAPI 없이도 함수로 바로 테스트할 수 있습니다.
- **장점 3 – 에러 처리 한 곳**: 서비스는 `NotFoundError`, `ConflictError` 만 던지고, `main.py` 가 404/409 로 바꿔 응답합니다.

## 3. Pydantic 요청 검증을 적용한 이유와 방식

**한 줄 요약**: 잘못된 데이터가 DB 에 들어가기 전에, 라우터 코드가 실행되기도 전에 자동으로 막기 위해서입니다.

```python
class DataCreate(BaseModel):
    date: dt.date = Field(...)                     # "2026-13-45" 같은 날짜는 거절
    value: int = Field(..., ge=0, le=1440)         # 음수나 하루(1440분) 초과 거절
    memo: str = Field("", max_length=100)          # 너무 긴 메모 거절

    @field_validator("date")
    def not_future(cls, v): ...                     # 미래 날짜 거절 (직접 만든 규칙)
```

- FastAPI 는 요청 본문을 이 모델로 바꾸면서 검사하고, 실패하면 **422** 와 함께 어떤 필드가 왜 틀렸는지 돌려줍니다. 프론트엔드는 이 메시지를 한국어 필드명으로 바꿔 토스트로 보여줍니다.
- `response_model` 로 응답 모양도 고정되어 Swagger 문서가 자동으로 정확해집니다.
- 프론트의 `<input min max required>` 는 사용자를 돕는 것이고, **진짜 방어는 서버(Pydantic)** 입니다. (브라우저 검사는 Swagger·curl 로 쉽게 우회 가능)

## 4. Firestore 에 데이터를 저장하고 CRUD 로 다루는 방법

**한 줄 요약**: 컬렉션 → 문서 → 필드 구조이고, `document(id).set / get / update / delete` 로 CRUD 합니다.

| 동작 | 코드 | API |
|---|---|---|
| Create | `collection("data").document("2026-11-22").set({...})` | `POST /api/data` |
| Read | `collection("data").order_by("date").stream()` | `GET /api/data` |
| Update | `document(id).update({"value": 120, ...})` | `PUT /api/data/{id}` |
| Delete | `document(id).delete()` | `DELETE /api/data/{id}` |

- **문서 ID = 날짜**로 정한 이유: 하루 1개 기록이 자동으로 보장되고, 같은 날짜로 또 추가하면 `get().exists` 로 확인해 409 를 돌려줄 수 있습니다.
- 대화는 자동 ID 문서에 `messages` 배열로 저장합니다. 목록 조회는 `select()` 로 제목·개수만 가져와 가볍게, 불러오기는 `GET /api/conversations/{id}` 로 전체 메시지를 가져옵니다.
- 서비스 계정 키(Admin SDK)는 보안 규칙을 거치지 않는 "관리자 권한"이므로 서버에만 두고, 브라우저는 Firestore 에 직접 접근하지 않습니다.

## 5. 컨텍스트 주입(데이터 요약 → 시스템 프롬프트)의 원리

**한 줄 요약**: AI 는 내 DB 를 모르니까, 질문할 때마다 "요약 메모"를 시스템 프롬프트에 붙여서 보내면 그걸 읽고 답합니다.

```python
messages = [
    {"role": "system", "content": "당신은 공부 기록 분석 비서입니다 ... [사용자 데이터 요약] 기간 ..., 합계 ..., 추세 ..."},
    *이전_대화_최근_10개,
    {"role": "user", "content": "이번 달 공부 얼마나 했어?"},
]
```

- `system` 메시지는 AI 의 "역할과 배경 지식"을 정하는 자리라서, 여기 넣은 숫자를 근거로 답합니다.
- 원본 120개를 통째로 넣지 않고 **요약**만 넣는 이유: 토큰(=비용)을 아끼고, AI 가 계산 실수하지 않도록 서버가 미리 정확히 계산해 주기 위해서입니다.
- "요약에 있는 숫자만 근거로, 없는 내용은 지어내지 말 것" 규칙으로 엉뚱한 답(환각)을 줄입니다.
- 한계와 보완: 요약에 없는 세부 내용(예: 10월 둘째 주)은 답하기 어렵습니다 → 보너스의 **도구 호출**로 AI 가 필요할 때 직접 조회하게 해서 보완했습니다.

## 6. 배포 환경에서 CORS / 환경 변수 / 키 관리가 필요한 이유

**한 줄 요약**: 프론트(vercel.app)와 백엔드(onrender.com)의 도메인이 달라서 CORS 허용이 필요하고, 키는 코드에 넣으면 유출되므로 환경 변수로 분리합니다.

- **CORS**: 브라우저는 보안상 다른 도메인으로의 요청을 기본 차단합니다. 백엔드가 응답에 "이 출처는 허용" 헤더를 붙여야 프론트가 결과를 읽을 수 있습니다. `ALLOWED_ORIGINS` 에 내 Vercel 주소만 넣어 다른 사이트의 브라우저 요청은 막습니다.
- **환경 변수**: 같은 코드가 로컬(.env)과 Render(대시보드 설정)에서 다른 값으로 동작합니다. 키를 바꿔도 코드 수정·재커밋이 필요 없습니다. 코디세이 주소/모델을 바꾸는 것도 환경 변수만 수정하면 됩니다.
- **키 관리**: GitHub 에 키가 올라가면 자동 수집 봇이 몇 분 만에 가져가 과금을 일으킬 수 있습니다. `.env`, `firebase-key.json` 은 `.gitignore` 로 막고, 프론트엔드에는 어떤 키도 두지 않습니다 (브라우저 코드는 누구나 볼 수 있으므로).
- **프론트엔드의 API 주소**는 비밀이 아니지만 배포마다 다르므로, Vercel 환경 변수 `API_BASE_URL` → 빌드 때 `config.js` 생성 방식으로 넣습니다.

### 💬 예상 질문 연습

- **Q. 요약을 프론트에서 받아서 AI 에 보내면 안 되나요?** → 사용자가 요약을 조작해서 보낼 수 있고, AI 키가 프론트에 노출됩니다. 서버가 직접 DB 에서 요약을 만들어 넣어야 신뢰할 수 있습니다.
- **Q. 대화 저장을 프론트가 따로 요청하지 않는 이유는?** → `/api/chat` 이 답변 직후 서버에서 자동 저장하므로, 네트워크가 끊겨도 질문/답변 쌍이 빠짐없이 남습니다. (`POST /api/conversations` 는 직접 저장이 필요할 때 쓰는 API)
- **Q. 왜 GET /api/conversations 에는 messages 가 없나요?** → 목록은 제목만 필요해서 가볍게 만들고, 클릭했을 때만 `GET /api/conversations/{id}` 로 전체를 불러옵니다(과제의 방식 A).
- **Q. 무료 서버가 잠드는 문제는?** → 접속 시 `/health` 로 먼저 깨우고, 늦으면 안내 배너를 보여줍니다.
